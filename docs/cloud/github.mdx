# GitHub Basics

## Repositories
A repository (or "repo") is the central location where your project files, folders, and revision history are stored. It acts as the project's workspace.

## Version Control (Git)
GitHub is built on top of Git, a distributed version control system. It allows you to track changes in your code, revert to previous versions, and manage project history without losing data.

## Branching
Branches allow you to diverge from the main codebase to work on new features or bug fixes in isolation.
- **Main/Master:** The default branch containing production-ready code.
- **Feature Branches:** Temporary branches used to develop specific features before merging them back.

## Pull Requests (PRs)
Pull Requests are the core of collaboration on GitHub. They allow you to notify team members about changes you've pushed to a branch. This provides a platform to:
- Review code changes.
- Discuss implementation details.
- Run automated tests before merging into the main branch.

## Commits
A commit is a snapshot of your repository at a specific point in time. Every commit includes a message describing what changes were made, creating a chronological "save point" for your project.
